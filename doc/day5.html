Django E-Commerce Project | Part 1: Build Steps with Syntax | Part 2: Explanations, Checks & Reflection

0. Today's Goal

A pending order from Day 4 gets two buttons: Pay with Khalti and Pay with eSewa. Both start as POST (CSRF-protected, owner-only). When the gateway sends the user back, the order is marked paid only after your server independently verifies the transaction: Khalti via the lookup API, eSewa via HMAC-SHA256 signature check plus the status API, and in both cases the amount must match order.total_amount. Marking paid is idempotent (select_for_update), so refreshes or duplicate callbacks cannot double-process. Both gateways are built; you pick one to keep later — the other is just two unused URLs.

"""Talks to Khalti / eSewa. Views never call requests directly."""
import base64
import hashlib
import hmac
import json
from decimal import Decimal, InvalidOperation

import requests
from django.conf import settings

TIMEOUT = 15


class GatewayError(Exception):
    pass


# ---------------- Khalti (ePayment v2) ----------------
def _khalti_headers():
    return {"Authorization": f"Key {settings.KHALTI_SECRET_KEY}",
            "Content-Type": "application/json"}


def to_paisa(amount):
    return int((Decimal(amount) * 100).quantize(Decimal("1")))


def khalti_initiate(*, order, return_url, website_url):
    payload = {
        "return_url": return_url,
        "website_url": website_url,
        "amount": to_paisa(order.total_amount),          # Khalti wants paisa (int)
        "purchase_order_id": str(order.pk),
        "purchase_order_name": f"Order #{order.pk}",
        "customer_info": {"name": order.full_name, "phone": order.phone},
    }
    try:
        r = requests.post(settings.KHALTI_BASE_URL + "epayment/initiate/",
                          json=payload, headers=_khalti_headers(), timeout=TIMEOUT)
    except requests.RequestException as exc:
        raise GatewayError(f"Khalti unreachable: {exc}") from exc
    if r.status_code != 200:
        raise GatewayError(f"Khalti initiate failed: {r.status_code} {r.text[:200]}")
    data = r.json()
    if "pidx" not in data or "payment_url" not in data:
        raise GatewayError("Khalti response missing pidx/payment_url")
    return data                                           # {"pidx", "payment_url", ...}


def khalti_lookup(pidx):
    """Server-to-server truth. Never trust the ?status= in the redirect."""
    try:
        r = requests.post(settings.KHALTI_BASE_URL + "epayment/lookup/",
                          json={"pidx": pidx}, headers=_khalti_headers(), timeout=TIMEOUT)
    except requests.RequestException as exc:
        raise GatewayError(f"Khalti unreachable: {exc}") from exc
    if r.status_code not in (200, 400, 404):
        raise GatewayError(f"Khalti lookup failed: {r.status_code}")
    return r.json()                                       # {"status": "Completed", "total_amount": ...}


# ---------------- eSewa (ePay v2, HMAC-SHA256) ----------------
def esewa_sign(message):
    digest = hmac.new(settings.ESEWA_SECRET_KEY.encode(), message.encode(),
                      hashlib.sha256).digest()
    return base64.b64encode(digest).decode()


def esewa_amount(amount):
    return f"{Decimal(amount):.2f}"


def esewa_form_fields(*, order, transaction_uuid, success_url, failure_url):
    total = esewa_amount(order.total_amount)
    code = settings.ESEWA_PRODUCT_CODE
    signed = "total_amount,transaction_uuid,product_code"
    message = f"total_amount={total},transaction_uuid={transaction_uuid},product_code={code}"
    return {
        "amount": total, "tax_amount": "0", "product_service_charge": "0",
        "product_delivery_charge": "0", "total_amount": total,
        "transaction_uuid": transaction_uuid, "product_code": code,
        "success_url": success_url, "failure_url": failure_url,
        "signed_field_names": signed, "signature": esewa_sign(message),
    }


def esewa_decode_and_verify(data_b64):
    """Decode ?data= from eSewa and check its HMAC. Returns dict or raises GatewayError."""
    try:
        payload = json.loads(base64.b64decode(data_b64).decode())
        fields = payload["signed_field_names"].split(",")
        message = ",".join(f"{f}={payload[f]}" for f in fields)
        received = payload["signature"]
    except (ValueError, KeyError, TypeError) as exc:
        raise GatewayError("Malformed eSewa data") from exc
    if not hmac.compare_digest(esewa_sign(message), received):
        raise GatewayError("eSewa signature mismatch")
    return payload


def esewa_status(*, transaction_uuid, total_amount):
    """Second, independent check: ask eSewa directly."""
    params = {"product_code": settings.ESEWA_PRODUCT_CODE,
              "total_amount": total_amount, "transaction_uuid": transaction_uuid}
    try:
        r = requests.get(settings.ESEWA_STATUS_URL, params=params, timeout=TIMEOUT)
        return r.json()                                   # {"status": "COMPLETE", "ref_id": ...}
    except (requests.RequestException, ValueError) as exc:
        raise GatewayError(f"eSewa status check failed: {exc}") from exc


def parse_amount(value):
    try:
        return Decimal(str(value).replace(",", ""))
    except InvalidOperation:
        return None

Step C — Idempotent state changes

payments/services.py
from django.db import transaction
from django.utils import timezone

from orders.models import Order


def mark_paid(order_id, ref):
    """Idempotent: a double callback / refresh can't pay twice."""
    with transaction.atomic():
        order = Order.objects.select_for_update().get(pk=order_id)
        if order.status == Order.Status.PAID:
            return order
        order.status = Order.Status.PAID
        order.payment_ref = ref
        order.paid_at = timezone.now()
        order.save(update_fields=["status", "payment_ref", "paid_at", "updated_at"])
        return order


def mark_failed(order_id):
    Order.objects.filter(pk=order_id, status=Order.Status.PENDING).update(
        status=Order.Status.FAILED, updated_at=timezone.now())

Step D + E — Views (Khalti and eSewa)

Flow: POST start → gateway page → gateway redirects back (GET) → server verifies → mark_paid → PRG redirect to order detail.

payments/views.py
import uuid

from django.conf import settings
from django.contrib import messages
from django.contrib.auth.decorators import login_required
from django.shortcuts import get_object_or_404, redirect, render
from django.urls import reverse
from django.views.decorators.http import require_GET, require_POST

from orders.models import Order

from . import gateways as gw
from .services import mark_failed, mark_paid


def _payable_order(request, order_id):
    # IDOR gate again: only the owner, only unpaid orders
    return get_object_or_404(Order, pk=order_id, user=request.user,
                             status__in=[Order.Status.PENDING, Order.Status.FAILED])


# ---------- Khalti ----------
@login_required
@require_POST
def khalti_start(request, order_id):
    order = _payable_order(request, order_id)
    try:
        data = gw.khalti_initiate(
            order=order,
            return_url=request.build_absolute_uri(reverse("payments:khalti_return")),
            website_url=request.build_absolute_uri("/"),
        )
    except gw.GatewayError as exc:
        messages.error(request, f"Could not start Khalti payment. {exc}")
        return redirect("orders:order_detail", order_id=order.pk)
    order.payment_ref = data["pidx"]          # remember which pidx belongs to this order
    order.status = Order.Status.PENDING
    order.save(update_fields=["payment_ref", "status", "updated_at"])
    return redirect(data["payment_url"])


@login_required
@require_GET
def khalti_return(request):
    pidx = request.GET.get("pidx", "")
    order = get_object_or_404(Order, payment_ref=pidx, user=request.user) if pidx else None
    if order is None:
        messages.error(request, "Missing payment reference.")
        return redirect("store:product_list")
    if order.status == Order.Status.PAID:
        return redirect("orders:order_detail", order_id=order.pk)
    try:
        info = gw.khalti_lookup(pidx)           # ignore GET ?status= -- ask Khalti
    except gw.GatewayError as exc:
        messages.error(request, f"Could not verify payment yet. {exc}")
        return redirect("orders:order_detail", order_id=order.pk)

    status = info.get("status")
    amount_ok = info.get("total_amount") == gw.to_paisa(order.total_amount)
    if status == "Completed" and amount_ok:
        mark_paid(order.pk, info.get("transaction_id") or pidx)
        messages.success(request, f"Payment verified. Order #{order.pk} is paid.")
    elif status in ("Pending", "Initiated"):
        messages.info(request, "Payment is still pending at Khalti. Refresh later.")
    else:
        mark_failed(order.pk)
        messages.error(request, f"Payment not completed ({status or 'unknown'}).")
    return redirect("orders:order_detail", order_id=order.pk)


# ---------- eSewa ----------
@login_required
@require_POST
def esewa_start(request, order_id):
    order = _payable_order(request, order_id)
    tx_uuid = f"{order.pk}-{uuid.uuid4().hex[:12]}"   # unique per attempt
    order.payment_ref = tx_uuid
    order.status = Order.Status.PENDING
    order.save(update_fields=["payment_ref", "status", "updated_at"])
    fields = gw.esewa_form_fields(
        order=order, transaction_uuid=tx_uuid,
        success_url=request.build_absolute_uri(reverse("payments:esewa_success")),
        failure_url=request.build_absolute_uri(
            reverse("payments:esewa_failure", args=[order.pk])),
    )
    return render(request, "payments/esewa_redirect.html",
                  {"fields": fields, "action": settings.ESEWA_FORM_URL})


@login_required
@require_GET
def esewa_success(request):
    try:
        data = gw.esewa_decode_and_verify(request.GET.get("data", ""))   # check 1: HMAC
    except gw.GatewayError as exc:
        messages.error(request, f"Payment rejected: {exc}")
        return redirect("store:product_list")

    order = get_object_or_404(Order, payment_ref=data.get("transaction_uuid"), user=request.user)
    if order.status == Order.Status.PAID:
        return redirect("orders:order_detail", order_id=order.pk)

    if gw.parse_amount(data.get("total_amount")) != order.total_amount:
        messages.error(request, "Amount mismatch. Payment not accepted.")
        return redirect("orders:order_detail", order_id=order.pk)

    try:                                                                  # check 2: ask eSewa
        st = gw.esewa_status(transaction_uuid=order.payment_ref,
                             total_amount=gw.esewa_amount(order.total_amount))
    except gw.GatewayError as exc:
        messages.error(request, f"Could not verify payment yet. {exc}")
        return redirect("orders:order_detail", order_id=order.pk)

    if data.get("status") == "COMPLETE" and st.get("status") == "COMPLETE":
        mark_paid(order.pk, st.get("ref_id") or data.get("transaction_code") or order.payment_ref)
        messages.success(request, f"Payment verified. Order #{order.pk} is paid.")
    else:
        messages.error(request, f"Payment not completed ({st.get('status', 'unknown')}).")
    return redirect("orders:order_detail", order_id=order.pk)


@login_required
@require_GET
def esewa_failure(request, order_id):
    order = get_object_or_404(Order, pk=order_id, user=request.user)
    mark_failed(order.pk)
    messages.error(request, "eSewa payment was cancelled or failed. You can retry.")
    return redirect("orders:order_detail", order_id=order.pk)

PART 2 — Explanations, Checks & Reflection

1. Never trust the redirect

The browser redirect (?status=Completed) is user-controlled input — anyone can type it. It only tells your server which transaction to check. Proof comes from a server-to-server call: Khalti /epayment/lookup/ or eSewa /transaction/status/, made with your secret key over HTTPS.

2. What HMAC proves (and doesn't)

eSewa signs total_amount,transaction_uuid,product_code (and more on the response) with a shared secret. A matching signature proves the data came from someone holding the secret and was not modified. It does not prove the money settled, and it does not stop a replay of an old valid message — that's why we also call the status API and check the order is not already paid. Use hmac.compare_digest, not ==, to avoid timing leaks.

3. Amount check

Verifying "Completed" is not enough: a user could pay Rs. 1 for a different pidx/uuid. Always compare the gateway's amount with order.total_amount (Khalti in paisa: Rs. 100 = 10000).

4. Idempotency

Users refresh, gateways retry. mark_paid locks the row with select_for_update() inside atomic() and returns early if already paid, so the state change happens exactly once.

5. Why start payment with POST

Starting a payment changes state (stores a new payment_ref). GET must be safe; POST + {% csrf_token %} stops another site from triggering it. The return URLs are GET because the gateways redirect that way — and they are safe because they only verify.

6. IDOR again

Every lookup filters by user=request.user. Another user's order id → 404, same pattern as Day 4. The return views find the order by payment_ref and owner.

7. Khalti vs eSewa

Khalti: JSON API, server initiates and gets a payment_url; verify with lookup. eSewa: browser POSTs a signed HTML form; response is base64 JSON with a signature; verify signature + status API. Khalti is simpler; eSewa teaches HMAC directly. Keep both or delete one app route later.

8. Django vs ASP.NET Core MVC

Django has no built-in HttpClientFactory; requests + a module-level service is the idiom. @require_POST ≈ [HttpPost]; {% csrf_token %} ≈ [ValidateAntiForgeryToken] (but Django enforces it globally by middleware). select_for_update ≈ UPDLOCK hint / EF transaction.
